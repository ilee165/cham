# Phase 5 — CI/CD Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Many steps are `az`/`gh` operations with expected outputs — those ARE the test cycle.

**Goal:** The four authored workflows actually working end to end: plan-on-PR with lint/security gates, environment-approved apply, nightly drift detection that opens issues, and the destroy kill switch — all authenticated to Azure via OIDC federation with zero stored cloud secrets.

**Architecture:** One Entra ID app registration with three federated credentials (main branch, pull requests, `lab` environment), Contributor on the subscription, and Storage Blob Data Contributor on the Terraform state account. GitHub holds only identifiers (client/tenant/subscription IDs) plus lab config values as secrets; Terraform authenticates natively via OIDC.

**Rebased 2026-08-08 onto the reviewed live workflows (DOC-B04).** The model this plan must extend — not replace — is already merged and reviewed:

- **PRs run credential-free checks only** (`plan.yml` job `static`, "Credential-free Terraform checks": fmt, tflint, checkov, `validate` with `-backend=false`). No plan and no cloud call happens on a pull request.
- **Saved plans are manual and privately stored**: `plan.yml` job `plan` runs only via `workflow_dispatch` on current `main`, resolves the randomized backend storage account by `az` lookup (masked), writes `tfplan` **and the complete human-readable output** to the private `tfplans` container (`lab/apply/<commit>-<run_id>-<attempt>/`, `--overwrite false` so a reviewed attempt is immutable), and uploads a short-lived artifact `terraform-plan-<sha>` containing only `plan-manifest.json` (repository, commit, run ID, plan SHA-256, plan blob path) and a sanitized action/address summary. Neither the plan binary nor its delta ever appears in a public artifact or log (NEW-CR-01 + PR #11 review); reviewers read `plan-output.txt` from the container before approving the hash.
- **Apply is a separate exact-artifact dispatch**: `apply.yml` (`terraform-apply-reviewed-plan`) takes `plan_run_id`, `source_commit`, the approved SHA-256, and a typed confirmation; it independently verifies environment reviewer protection, current `main`, the source run, the manifest binding (including that the manifest's `plan_blob` matches the verified run identity), then fetches the plan blob from the private container and re-verifies its SHA-256 before an environment-gated apply. A merge never applies anything.
- **Destroy is two-stage**: `destroy.yml` `operation=plan` (+`confirm=PLAN_DESTROY`) produces a reviewed destroy artifact; `operation=apply` (+ run/hash inputs, `confirm=DESTROY`) applies exactly that artifact.
- **Drift is live and public-edge-only**: `drift.yml` already runs the Phase 4 CLI's 0/2/1 contract against the committed `desired-records.json` (ADR-006 as amended), authenticated with the repository-level **read-only** `CLOUDFLARE_API_TOKEN_RO`, no Azure credentials, and fails closed on unexpected exit codes via `scripts/check-drift-exit.sh`.

Phase 5's remaining work is: the OIDC identity and settings that let the dispatched plan/apply/destroy jobs actually authenticate; a Cloudflare plan/apply pair that mirrors the exact-artifact trust chain and the partial-backend discovery; extending drift to gate the Azure edge on lab presence; and the carried-forward Phase 4 items below.

**Tech Stack:** GitHub Actions, `gh` CLI, `az` CLI, Entra ID workload identity federation, `astral-sh/setup-uv`, tflint (+azurerm ruleset), checkov.

## Global Constraints

- **No stored cloud credentials.** `AZURE_CLIENT_ID`/`AZURE_TENANT_ID`/`AZURE_SUBSCRIPTION_ID` are identifiers, not secrets (stored as secrets anyway, harmless). No client secrets, no PATs, no storage keys, ever. Cloudflare has no OIDC federation, so it holds the only true secrets — **two tokens with distinct blast radii (DOC-B06, least privilege is a hard constraint):**
  - `CLOUDFLARE_API_TOKEN_RO` — zone-scoped **read-only** (Zone:Read + DNS:Read), a **repository** secret. This is what the unattended scheduled drift job uses today and must keep using: a bug in an unattended job can then misreport, never mutate.
  - `CLOUDFLARE_API_TOKEN` — zone-scoped edit (Zone:Read + DNS:Edit), stored **only in the protected `lab` environment**, reachable solely by environment-gated jobs a human approved. Never referenced from a scheduled or PR-triggered job.
- Prerequisites: Phase 2 (backend storage account, applied stack), Phase 4 (reconciler CLI + `desired-records.json`) for Tasks 4–5. Tasks 1–3 need only Phase 2.
- Exit-code contract from Phase 4 is law: 0 converged / 2 drift / 1 error. The drift workflow keys off it.
- Workflow YAML changes are only testable by running them — every workflow gets at least one real, evidenced run (URL captured) before the phase closes.
- Evidence: `docs/evidence/phase5/notes.md` collects run URLs and outcomes.

- [ ] **Step 2: Add the `plan-cloudflare` job to `plan.yml` (dispatch-only, full backend discovery)**

Append as a sibling of `plan`, with the same guards: `if:
github.event_name == 'workflow_dispatch' && github.ref == 'refs/heads/main'`,
`needs: static`, `id-token: write`. Two things the earlier draft of this step
got wrong and DOC-B05 flagged: **bare `terraform init` cannot initialize this
root** (its backend is deliberately partial — `main.tf` pins
resource group/container/`key: cloudflare.tfstate` while the storage account,
subscription, and tenant stay out of version control), and a plan that is
never uploaded can never be applied. Mirror the Azure job exactly:

```yaml
  plan-cloudflare:
    if: github.event_name == 'workflow_dispatch' && github.ref == 'refs/heads/main'
    needs: static
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
    env:
      ARM_USE_OIDC: "true"
      ARM_CLIENT_ID: ${{ secrets.AZURE_CLIENT_ID }}
      ARM_TENANT_ID: ${{ secrets.AZURE_TENANT_ID }}
      ARM_SUBSCRIPTION_ID: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
      TF_IN_AUTOMATION: "true"
    defaults:
      run:
        shell: bash
        working-directory: terraform/cloudflare
    steps:
      - uses: actions/checkout@v4
      - uses: hashicorp/setup-terraform@v3
        with:
          terraform_version: "~1.9.0"
      - name: Azure login (OIDC)          # backend account lookup only
        uses: azure/login@v2
        with:
          client-id: ${{ secrets.AZURE_CLIENT_ID }}
          tenant-id: ${{ secrets.AZURE_TENANT_ID }}
          subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
      - name: Resolve remote-state account   # same discovery as the lab job
        id: backend
        run: |
          set -euo pipefail
          storage_account_name="$(az storage account list \
            --resource-group rg-cham-tfstate --query '[0].name' --output tsv)"
          [[ -n "$storage_account_name" && "$storage_account_name" != "None" ]] \
            || { echo "::error::No state storage account in rg-cham-tfstate."; exit 1; }
          echo "::add-mask::$storage_account_name"
          echo "name=$storage_account_name" >> "$GITHUB_OUTPUT"
      - name: Create saved plan and manifest
        env:
          # The RO token is enough for a plan (reads only) — the edit token
          # stays behind the environment gate until apply.
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN_RO }}
        run: |
          set -euo pipefail
          terraform init -input=false -reconfigure \
            -backend-config="storage_account_name=${{ steps.backend.outputs.name }}" \
            -backend-config="subscription_id=${ARM_SUBSCRIPTION_ID}" \
            -backend-config="tenant_id=${ARM_TENANT_ID}"
          # NEW-CR-01 + PR #11 review: neither the plan binary nor its
          # complete delta may reach a public artifact or log — both go to
          # the private tfplans container, exactly like plan.yml does for
          # the lab stack, with the run attempt in the prefix and
          # --overwrite false so a reviewed attempt is immutable.
          blob_prefix="cloudflare/apply/${GITHUB_SHA}-${GITHUB_RUN_ID}-${GITHUB_RUN_ATTEMPT}"
          terraform plan -input=false -no-color -out=cloudflare.tfplan > cloudflare-plan-output.txt 2>&1
          plan_sha256="$(sha256sum cloudflare.tfplan | awk '{print $1}')"
          jq -n --arg kind "apply-cloudflare" --arg repository "$GITHUB_REPOSITORY" \
            --arg commit_sha "$GITHUB_SHA" --arg workflow_run_id "$GITHUB_RUN_ID" \
            --arg plan_sha256 "$plan_sha256" \
            --arg plan_blob "${blob_prefix}/cloudflare.tfplan" \
            '{kind:$kind, repository:$repository, commit_sha:$commit_sha, workflow_run_id:$workflow_run_id, plan_sha256:$plan_sha256, plan_blob:$plan_blob}' \
            > cloudflare-plan-manifest.json
          echo "SHA-256: $plan_sha256" >> "$GITHUB_STEP_SUMMARY"
          az storage container create --name tfplans \
            --account-name "${{ steps.backend.outputs.name }}" \
            --auth-mode login --output none
          for file in cloudflare.tfplan cloudflare-plan-output.txt; do
            az storage blob upload \
              --account-name "${{ steps.backend.outputs.name }}" \
              --container-name tfplans \
              --name "${blob_prefix}/${file}" \
              --file "$file" --auth-mode login --overwrite false --output none
          done
          rm -f cloudflare.tfplan cloudflare-plan-output.txt
      - uses: actions/upload-artifact@v4
        with:
          name: cloudflare-plan-${{ github.sha }}
          path: terraform/cloudflare/cloudflare-plan-manifest.json
          if-no-files-found: error
          retention-days: 3
```

(The pinned regression test `ddi-reconciler/tests/test_workflow_plan_confidentiality.py`
fails the suite if any workflow reintroduces a `tfplan`/`*.tfplan` path into an
`upload-artifact` step — this job must satisfy it from its first draft.)

- [ ] **Step 3: Add the `apply-cloudflare` job to `apply.yml`, behind the same verification chain**

Reuse `apply.yml`'s existing input/verification structure verbatim — the job

## Exit Criteria (all must hold)

1. Zero stored cloud credentials: secrets list contains only OIDC identifiers, lab config values, and the two zone-scoped Cloudflare tokens — read-only at repository level, edit-capable only in the `lab` environment — no client secrets, PATs, or storage keys anywhere.
2. A PR touching `terraform/**` cannot merge without the credential-free gate green (fmt + tflint + checkov + backend-less validate + reconciler suite). Plans are produced only by manual dispatch on current `main` and are readable in the run summary/artifact.
3. Nothing applies on merge: both stacks (lab, cloudflare) apply from CI only through the exact-artifact dispatch — verified run/commit/hash — behind a human-approved `lab` environment gate.
4. nightly-drift: green + silent when converged; opens a labeled issue containing the exact diff on real drift; fails loudly on exit 1 AND on any exit code outside the 0/1/2 contract; skips the Azure edge cleanly when the lab is destroyed; runs on the read-only token.
5. destroy.yml empties the lab from the Actions UI through its two-stage plan-then-apply gate with typed confirmations.
6. checkov and tflint pass with zero unaddressed findings — every skip carries a written justification.
7. All five workflow runs evidenced by URL in `docs/evidence/phase5/notes.md`; architecture diagram + resolution-path table published; all five README phase boxes checked.
8. Every item in "Carried forward from Phase 4" below is either done or re-deferred with a written reason.

## What Completion Looks Like

The repo operates itself: propose a change and CI shows exactly what would happen; merge it and nothing touches Azure until a human clicks approve; every night the edges are compared against committed truth and tampering becomes a labeled issue with the diff inline; and the whole lab can be vaporized from a phone with one typed word. A reviewer walking the repo sees plan output on PRs, drift issues with evidence, justified scanner skips, ADRs for every tradeoff, and — nowhere — a credential.
